# 积分计费

主动使用 AI 按实际用量扣分，开工前先确认预算。
用户只看积分账目，模型积分系数仅超管可见。

本文依据[已确认需求](../.claude/md/20261103_153904_积分计费系统恢复与三端完善.md)。

## 余额与预算

| 名称 | 含义 |
|---|---|
| 总余额 | 尚未最终消费的积分，包含预留部分 |
| 预留积分 | 进行中操作占用的预算，尚未扣费 |
| 可用余额 | 总余额减去预留，可用于新操作 |
| 本次预算 | 用户确认的本笔扣费上限 |

例如：总余额 80.00 分，预留 20.00 分，可用 60.00 分。
若最终消费 7.50 分，释放剩余预留 12.50 分。
结算后总余额与可用余额均为 72.50 分。

- 预算必须为正数，精度为 0.01 分。
- 预算不能超过提交时的可用余额。
- 多笔操作不能重复占用同一份可用积分。
- 不自动追加预算，不允许欠费；超预算部分由平台承担。
- 默认预算按历史用量测算，用户启动前可以修改。

## 一笔操作怎样结算

一次发送或生成请求构成一笔操作。
正常生成、审稿和自动修改都属于本笔创作。
管理员在创作端主动使用 AI，同样计费。

| 情况 | 积分处理 |
|---|---|
| 正常完成 | 按已核实用量结算，释放未用预留 |
| 故障后重试成功 | 故障调用和恢复重试免费，正常创作照常计费 |
| 最终因系统或供应商故障失败 | 本笔净消费为零，全部预留恢复可用 |
| 用户主动停止 | 按已核实用量结算，不超过预算 |
| 预算用尽 | 按量结算，保留已有内容，不自动续费 |
| 用户因不满意重新生成 | 视为新操作，确认新预算后计费 |
| 调用缺失必要用量 | 缺失调用不估扣，未知部分由平台承担 |
| 平台测试、评估、进化 | 不扣用户积分 |

故障退款只覆盖本笔，不退其他已完成操作。
预算耗尽后，用户补分或调整预算，再主动继续。
继续操作保留已有产物，不重复已完成副作用。

## 系数与精度

- 超管分别配置正常输入、缓存输入和输出系数。
- 系数单位是**积分/百万 Token**，不依赖人民币成本。
- 消耗为各类用量乘对应系数，再除以一百万。
- 全部调用先精确累加，再整笔四舍五入到 0.01 分。
- 不逐调用取整，不重复计算缓存和已包含的思考用量。
- 缺失系数不等于零；配置不完整时拒绝新计费操作。
- 每笔操作保留接受时的系数，修改只影响新操作。

后台沿用 `/api/admin/billing/prices/{model}` 路径。
`input_per_million`、`output_per_million`、`cached_per_million`
均表示积分系数，不是人民币单价。
内部 `cost`、`platform_cost` 表示未取整积分量。

用户接口不返回系数、系数快照或逐调用计算金额。
用户仍可查看模型用量、免费重试、缺失用量及扣退原因。
匿名 `/api/credits/rules` 只返回开关、默认预算、群号及协议版本。
官网不展示模型价格、采购成本或人民币换算。

## 掉线、重连与结算恢复

- 掉线或关闭客户端，后台继续原任务，预算不变。
- 重连复用原操作，重放原事件或读取已保存结果。
- 同一请求重传不新建任务，不重复扣分或退款。
- 明确点击停止，才按主动停止规则结束。
- 服务重启先核对原任务，不自动重开收费操作。
- 原任务已终止且无法继续，按系统故障全退。

结算失败显示“处理中”，不伪装为扣退成功。
余额查询失败显示错误与重试入口，不显示假零余额。
服务和账目数据恢复后，五分钟内补齐待处理账目。

## 发放与迁移

- 仅超管能手动加减积分，或配置邀请码发分。
- 调整必须填写原因，保留操作者与变动后余额。
- 同一调整失败重试复用请求编号，不能重复到账。
- 邀请码兑现只发一次积分；积分永久有效。
- 减分不得占用预留，也不得使可用余额变负。
- 本阶段不接在线支付、订阅或每日自动赠分。

| 迁移对象 | 处理 |
|---|---|
| 旧正余额 | 原数保留 |
| 旧零余额 | 保持为零 |
| 旧负余额 | 归零，并记录原余额、归零金额及迁移来源 |
| 历史流水 | 保留，不重写；迁移重跑不重复发分 |
| 免费期用量、启用前已接受任务 | 不追扣 |
| 旧客户端 | 可阅读已有内容；新计费操作须升级并确认预算 |

## 启用与安全回退

1. 首次迁移前备份旧账，明确计费启用边界。
2. 根据历史用量测算默认预算，配置有效模型系数。
3. 验证预算、免费路径、迁移与结算恢复后启用。
4. 需要停止新计费时，关闭后台计费开关。
5. 已接受操作仍按原预算和原系数结算。

**关闭开关不删除账本，也不免除待结算责任。**
必须保留 v2 余额、预留、流水、结果和待结算凭据。
已有新账后，不得恢复旧数据库快照抹掉发分或消费。
回退应用也须保留结算恢复能力，不得恢复旧负债规则。

默认预算的测算依据与样本留在受控运维证据中。
公开文档不记录实际系数、采样明细、主机或凭据。
