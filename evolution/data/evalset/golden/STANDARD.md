# 玄幻大纲评测集内容质量标准（STANDARD）

> 需求来源：REQ-20260920-150253（FR-001/FR-004）。本文件是 golden/growing 数据集
> case 的编写与准入标准，也是扩量评审的依据。评分锚点不在本文件——单一事实源在
> `evolution/app/benchmark/rubric_v3.py`。

## 0. 输出契约（对齐被测 Agent 的交付物）

被测 Agent 的输出 = **大纲三件套**：

| 件套 | 逻辑键 | 判定 |
|---|---|---|
| 主线 | storyline | 齐全、非空、非占位符 |
| 人物 | character | 齐全、非空、非占位符 |
| 世界观 | worldview | 齐全、非空、非占位符 |

- benchmark 层不定义三件套内部结构（由 harness prompt 约束）。
- 规则项「交付完整」只做上述代码判定，不打主观分。

## 1. 三档留白度字段表

demand 按留白度分三档。档位在元信息头 `blank_level` 标注（full / semi / minimal）。

### 字段清单与档位要求

| 层 | 字段 | full 全填 | semi 半留白 | minimal 极简 |
|---|---|---|---|---|
| 核心层 | 体裁类型（主类型+次类型） | 必填 | 必填 | 只到「玄幻+子流派」 |
| 核心层 | 一句话故事（logline） | 必填 | 必填 | 必填 |
| 核心层 | 核心卖点/爽点钩子 | 必填 | 必填 | 留白 |
| 核心层 | 金手指（来源/边界/代价/成长路径） | 必填 | 必填 | 留白 |
| 核心层 | 篇幅档位 | 必填 | 必填 | 必填 |
| 核心层 | 目标配比（主线/支线/角色线/暗线） | 必填 | 必填 | 留白 |
| 设定层 | 世界观·时空背景 | 必填 | 一句 | 留白 |
| 设定层 | 世界观·核心设定（体系/社会/规则） | 必填 | 留白 | 留白 |
| 设定层 | 世界观·差异化卖点 | 必填 | 一句 | 留白 |
| 设定层 | 主角设定（身份/欲望/恐惧/弧光/起点） | 必填 | 必填 | 留白 |
| 设定层 | 配角与关系网 | 必填 | 留白 | 留白 |
| 风格层 | 叙事风格基调 | 必填 | 一句 | 留白 |
| 风格层 | 视角与节奏 | 必填 | 留白 | 留白 |
| 风格层 | 禁忌与红线 | 必填 | 留白 | 留白 |

### 各档定位

- **full（全填）**：考组装与兑现精度。需求全给定，Agent 的任务是结构化成三件套
  且不漂移。是跑分对比的稳定基线。可含增强字段（目标受众 / 对标参考 / 主题与
  价值观），不强制。
- **semi（半留白）**：考「给定内核 + 补全自洽」。核心创意、金手指、主角给定；
  世界观体系、配角、支线由 Agent 创作补全，补全部分必须与给定内核无矛盾。
- **minimal（极简）**：考纯创作力。只有一句话创意 + 题材 + 篇幅。Agent 自由发挥，
  「需求兑现」只判承诺点，质量主要由其余四维承担。

## 2. 承诺点规范

每条 demand **必须**以独立小节承载承诺点：

```markdown
## 承诺点（不可漂移项）

1. <单句、可核对的陈述>
2. …
```

规则：

1. **可核对**：每条承诺判「兑现 / 未兑现」不需要主观裁量。
   好例子：「主角金手指是能解析复刻兵器技法」；坏例子：「故事要有感染力」。
2. **数量**：full / semi 档 6-10 条；minimal 档 3-5 条。
3. **一致性**：承诺点必须与正文字段一致——正文字段是承诺点的展开，
   两者不得矛盾。
4. **不矛盾**：承诺点之间不得互相冲突。
5. **评分衔接**：「需求兑现」维度只判承诺点兑现与漂移；留白部分不计入该维
   （质量由设定自洽/人物塑造/情节构造/节奏结构四维兜底）。
6. Agent 可见承诺点（DEC-011）。这是显式需求的兑现纪律，不是应试。

## 3. 通用质量线（不分档）

1. **题材限定**：主类型 = 玄幻；子流派在元信息头 `subtype` 标注。
2. **元信息头**：保持 HTML 注释块结构（文件起始，前 300 字符内），程序按字段
   逐条正则解析。现有键保留：`mode: auto`、`status: confirmed`、`genre: 玄幻`、
   `subtype: <子流派>`、`title: <书名（题材）>`、`updated`、`note`。
   **新增键**：`blank_level: full | semi | minimal`。
3. **注册校验**（`scripts/register_golden.py` 硬性要求）：
   - 元信息头含 `title` 与 `status: confirmed`；
   - 全文 ≥ 500 字符（minimal 档也要满足）。
4. **留白可补全**：留白字段必须是 Agent 能独立创作补全的，不得依赖未给出的
   前提（坏例子：留白世界观却要求呼应某未给出的上古设定）。
5. **正文规范**：markdown；层级为 `# 创作需求文档` → `## 核心层/设定层/风格层`
   → `## 承诺点（不可漂移项）`；semi 档留白字段直接省略小节，不写「待补充」
   等占位字样（会触发交付完整规则项的占位符检测语义混淆）。

## 4. 扩量标准（新增 case 准入）

1. 满足第 3 节通用质量线 + 第 2 节承诺点规范 + 所属档位字段表。
2. **子流派互补**：新 case 的子流派与现有集不重复；优先补主流派缺口
   （候选：系统流、争霸流、无敌流、家族修仙流等）。
3. **分档比例**：维持 full:semi:minimal ≈ 2:3:1 的分布。
4. **用户终审**：新增 case 必须经用户逐条终审后才可注册定稿。
5. **备选方向**（暂不实施，扩量时评估）：
   - 内在矛盾 demand（对抗 case）：表单自相矛盾的诉求，考 Agent 的取舍与澄清；
   - judge 专用承诺点文件：承诺点对 Agent 不可见，考自然兑现（需改评分管道）。

## 5. 修订流程

1. 修改/新增 `evalset/golden/<case-id>/demand.md`；
2. `python -m scripts.register_golden --dry-run` 校验；
3. 校验通过后去掉 `--dry-run` 正式注册（dataset_meta 登记 + golden 内容指纹重锁）；
4. golden 目录是镜像种子（`Dockerfile.evolution` COPY），部署重建后由
   entrypoint 同步到 volume，服务器侧同样执行一次注册脚本完成重锁。
