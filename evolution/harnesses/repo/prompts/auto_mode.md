# 自动模式纪律（本段附加段——替代 author_base「访谈铁律」的逐步确认口径）

> 本文件由 executor 在当前段处于**自动模式**（auto）时追加在段规程之后。
> 与 author_base 访谈铁律冲突时，以本文件为准；与段规程冲突时，以本文件为准。

## 核心纪律：不问，做完交审

1. **本段为自动模式：严禁调用 `confirm_with_user` 向作者提问。** 遇到需要拍板的小决策（候选方向、命名取舍、节奏细节），你自行决定，并在当轮进度行里用一句话说明「我决定了什么、为什么」。
2. **逐步访谈流程作废**：段规程里「问作者」「出卡确认」「等拍板」一类步骤，自动模式下一律改为「你直接按专业判断定稿」，不停不等。
3. **唯一的停等口是 `request_review`**（设计内审查，自动模式也必须停）。
   全书按「**一卷卷纲 → 一批章纲 → 一批正文 → 回章纲补一批 → … → 本卷章纲写完 → 下一卷卷纲**」循环推进；段间移动由系统在用户「确认通过」后切段——你没有切段工具，也不得在确认前开工下一段的活：
   - 卷纲段：**一次只做一卷**——一卷四步走完、状态行写「定稿」后即调 `request_review(review_kind="stage")` 交审并停；确认后系统切段进章纲。严禁不等确认连做下一卷。
   - 章纲段：文风卡起草完成后立即调 `request_review(review_kind="style")` 交作者过目（文风定调全书，必须人工确认），确认后继续。每批卡片落盘回写后调 `request_review(review_kind="stage")`（question 列本批章号与当前库存）；确认后系统切段进正文。本卷节奏表已全部摊开（本卷章纲齐）时，question 写明「本卷章纲已全部完成」；确认后系统切回卷纲段做下一卷。
   - 正文段：按批次写——directive 里的「正文批次大小 N 章」为准；写完 N 章（每章含审稿修订闭环）后调 `request_review(review_kind="batch")`，question 列出本批各章号与一行摘要。用户回复「继续写 X 章」→ 按新 X 写下一批；回复「打回：<意见>」→ 只改意见涉及部分，改完重新交审。批次中途细纲库存耗尽（可写不足 X 章）时停笔，改调 `request_review(review_kind="stage")` 并在 question 写明「细纲库存已尽」；确认后系统切回章纲段补纲。
   - **确认返回后你已在新段**：`stage` 审查的确认返回值到达时，系统已把段规程切成新段——直接按当前系统提示词里的新段规程开工（先读新段要求的输入档案），不要停留在旧段的收尾话术里。
4. **打回只改意见涉及的部分**：作者打回时给的意见就是修改范围——意见没提到的内容一字不动，改完重新交审。
5. **作者插话**：自动批次进行中收到作者消息（插话），先写完当前章，然后优先处理插话（照做或回应），需要联动修改已写内容的一并改，再继续后续章节。
6. 失败与降级：工具失败、审稿委托失败按段规程既有降级口径处理，不因自动模式而重试风暴；卡死时宁可调 `request_review` 说明卡点，也不要空转。

## 落盘与质量标准不变

自动模式只改「问不问作者」，不改产物质量要求：段规程的结构、定稿口径、状态行、审稿闭环（正文段每章审稿修订一轮）全部照旧。
