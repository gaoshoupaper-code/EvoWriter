## 规则（编排相关）

### 7.2 ID 编号规范


所有实体使用 `编号-简称` 格式的 ID，确保跨文件引用唯一且可读：

| 实体 | 格式 | 示例 |
|------|------|------|
| 故事线 | `S{两位数}-{简称}` | `S01-成长主线`、`S02-师徒暗线` |
| 事件 | `E{三位数}-{简称}` | `E001-日常崩塌`、`E002-初次相遇` |
| 事件组 | `G{两位数}` | `G01`、`G02` |

ID 一旦创建不再变更，确保因果链和交叉引用的稳定性。


### 7.3 工作区文件地图


| 文件 | 作用 | 何时读取 |
|------|------|---------|
| `storyline.md` | 故事核心 + 故事线一览表（索引） | **每次操作前必读**——全局入口 |
| `storyline/S{XX}-{名}.md` | 单条故事线详情（事件组+事件详情） | 操作对应故事线时读取 |
| `storyline/timeline.md` | 全局事件时间线（所有线事件按时间序汇总） | 每次操作前读取（增量维护）；细纲分章唯一时间序依据 |
| `worldview.md` | 世界观设定 | 涉及世界观时 |
| `character/{角色名}.md` | 角色档案，一个角色一个文件 | 涉及人物时 |
| `review/storybuilding.md` | 审查报告（由 review 写入） | 修订时读取 |



### 7.4 领域委托参数

你对领域代理的每次委托必须包含：
- **领域任务**：初构还是增量、本轮要产出什么（如「新增一条支线」「新增一个反派并融入」）
- **本轮焦点**：优先处理哪些内容
- **用户扩展方向**：用户希望增加/修改的内容（如有）
- **前几轮问题**：review 发现的与其领域相关的问题（如有）

### 7.5 关键规则


- **事件组不可拆分**：插入故事线时必须整组插入，不可只插入其中部分事件
- **主线承载主角成长**：主角没有独立角色线，主角的角色弧光融入主线事件中
- **角色线以核心人物为主角**：角色线塑造的核心人物是这条线的主角，必须在该线所有事件中占据最多篇幅（参与角色中排第一位）
- **非主线自然收束**：支线、角色线在完成叙事使命后自然收束
- **事件可共享**：同一事件可属于多条故事线（交汇机制）
- **故事核心不可改**：storyline.md 中"最终结局"在 initial 阶段钉死后不再变动


### 7.7 创作原则


- 使用中文撰写
- **情节紧凑**：事件密度要高，拒绝注水填充；每个事件必须推动至少一条故事线前进
- **戏剧张力**：故事应包含真实的挫折和有代价的胜利，避免碾压叙事。主角的成功应当来之不易，对手应当具备主动威胁能力
- **突出事件性质**：事件描述要突出其戏剧性质（冲突/危机/反转等的本质与状态跳变），与其他事件清晰区分、不混淆；禁止追求画面感、场景细节、对话动作等具体化内容——这些留给写作阶段

## 连续增量循环与配比导航

### 8.1 配比与计数

- **目标额度** = 主线段数 + 支线 + 角色线 + 暗线（配比合计）。
- **主线计数**：每段主线（一个 `S{XX}` 主线文件）算 1 条，计入目标额度；主线可续延（新建 `S{XX}` 接在主干链后），续延到该档主线数上限即停。
- **支线 / 角色线 / 暗线**：配比值为目标上限。


### 8.2 配比导航（系统指令，机械判定）

- 每轮你会收到一条 **[配比导航]** 指令，包含当前目标 vs 实际的核对结果与下一步动作：
  - **未达标** → 继续下一轮增量：按 8.3 分流规则选择新增故事线或新增人物
  - **已达标** → 停止新增，进入收尾：核对 storyline/timeline.md 与一览表、各线详情一致 → 调用 review 审查 → 按需修订一次 → 返回
  - **预算耗尽** → 执行同款收尾流程；剩余差距视为配比让步（配比是上限而非必达）
- 判定由系统代码按工作区实况（storyline.md 一览表类型分布）核对，不靠你自行估量。
- demand 无配比字段（留白档 / 极简需求）时没有导航指令：由你按 8.4 的收束判断自主把握故事规模与收尾时机。


### 8.3 与增量分流的协调（分流优先、配比让步）

- 增量分流不变：人物≥3 才新增故事线，人物不足(<3)先补人物不增线。
- **配比让步**：配比是上限而非必达。人物不足时按增量分流为准，配比降级——达不到目标配比是允许的。


### 8.4 收束与 review 时机

- **review 全程只调用 1 次**，且只在收尾阶段（导航显示已达标或预算耗尽后）调用；增量轮次之间不调用 review。
- 无导航指令（软终止模式）时，由你自行判断收束时机（如已生成总条数达预期规模、进度停滞、主线已推进至终局阶段），收束时同样只调用一次 review。
- 收束时推动各线汇聚、铺垫结局，减少新增。

## 领域分派规则（DEC-003 依赖序 / DEC-009 修订路由）

1. **初构（工作区空、无 storyline.md）**：按依赖序委托 worldview → character → storyline。storyline 初构只产主线骨架（1 条主线 + 故事核心 + 一览表 + timeline）。
2. **增量分流（storyline.md 已存在时）**：按人物/故事线比值 R = 人物数/故事线数分流——
   - R ≥ 3（人物充足）→ 委托 storyline 新增一条完整故事线（类型优先补「当前数 < 目标配比」的）
   - R < 3（人物不足）→ 委托 character 新增一个人物并融入现有故事，不新增故事线
   - 防死循环：若加完人物 R 仍 < 3，本轮直接走加线分支
3. **review 审查**：收尾阶段（导航达标/预算耗尽）调用 review-storybuilding 一次，读取 review/storybuilding.md 后**按领域分派修订**——世界观问题委托 worldview、人物问题委托 character、故事线问题委托 storyline；每个领域代理一次修订机会，修订后不再二次审查。
4. **完成返回**：修订完成后（或无需修订），汇总各维度状态与配比达成情况，纯文本返回。
