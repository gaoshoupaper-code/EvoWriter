# storybuilding-initial

首次故事骨架构建流程。**内容规范唯一真相源是技能 storybuilding-specs**（质量总则/世界观/人物档案/故事线/事件/文风/物品卡全部在其中，系统提示词只管流程）——步骤 3 动笔前读取（本会话首次读取后不必重读），跳读等于无规范写作。四个硬性约束：
1. **只生成主线（1 条）**。支线 / 暗线 / 角色线一律交给增量 Skill 后续添加，初构阶段不生成。
2. **storyline.md "故事核心"段落的"最终结局"初构定为草稿基线**：拍板确认的方向为初版草稿，后续轮次可随叙事需要修订。
3. **"设计原则"初构落盘后钉死**（系统校验）：内容取自拍板方案包关键锚点中的设计原则。
4. **形态先行**：主线事件表落笔前，「节奏曲线」的四槽位目标形态必须已定（specs 4.1），事件张力对着形态走。

## 工作流程

### 步骤 1 — 读取需求背景

读取 `demand.md`，了解用户需求和创作背景。
- demand.md 由主代理维护，你只能读取，不能写入、编辑或删除。

### 步骤 2 — 读取已有产物

读取工作区中已有的文件（首次构建时可能不存在，属于正常情况）。

### 步骤 3 — 产出骨架

先完整读取技能 **storybuilding-specs**（内容规范唯一真相源），再按其规范产出骨架。

写入顺序：
1. `worldview.md`（世界观是底层基础）
2. `character/*.md`（人物在世界观中活动）
3. `storyline.md`（六字段故事核心——设计原则按拍板方案、节奏曲线先画目标形态——再落主线 1 个区块的完整事件表）
4. `hooks.md`（主线事件表落定后建立钩子登记首表——本次主线事件对读者吊起了什么，按 storybuilding-specs 第八章九列格式登记，埋设/推进/兑现事件名逐字引用事件表）

**storyline.md 是唯一手写的故事线产物**——不要创建 storyline/ 目录，不要创建 timeline.md（全景时间轴由系统自动派生）。

**最小骨架必须包含：**
- storyline.md 中的"故事核心"六字段（Logline、设计原则、核心主题、类型基调、节奏曲线=槽位目标形态、最终结局）
- storyline.md 中的主线区块（`## {主线名} · 主线 · 活跃` + 线头两行 + 完整事件表；非交汇事件数在 storybuilding-specs 参考区间内自定（主线经验值 ~12），时序号 T1 起，每行含张力/爽点标注（specs 5.5）
- 至少 1 个主角档案（角色类型标注为"主角"）
- 基础世界观框架（至少包含时代背景、核心冲突根源）
- `hooks.md` 钩子登记首表（主线关键转折埋钩，建议 4-6 条；九列格式与层级/类型/状态枚举见 storybuilding-specs 第八章）

初构阶段不生成支线 / 暗线 / 角色线，它们由增量 Skill 按需添加。

未产出的维度直接留空，由后续轮次自然补上，不写「待…」类占位待办。

#### 核心人物与角色线约束

角色类型定义与角色线资格见 storybuilding-specs 人物档案规范（主角/核心人物/Boss/配角）。本阶段硬性约束：

1. 核心人物 ≤ 2 人（不含主角）。宁少勿多——后续增量 Skill 可按需引入。
2. 只有核心人物/Boss 可拥有角色线，每人最多 1 条；配角禁止建线，叙事功能写在事件表「角色」列。

### 步骤 4 — review 审查（本单元完成后必审一次）

骨架产出完成后调用 review 子代理审查（**本轮产物有任何修改即须审查**——未审直接返回会被系统闸门拦回）。review 调用上限由系统自动管理，超出上限的调用会被拦截。

**调用时在任务描述中附加**：
"本次为首次骨架构建，请侧重审查结构完整性和可扩展性。骨架阶段不要求内容丰富度，但世界观核心规则的逻辑此轮就要立住。"

**单次审查策略**：无需修改 → 直接返回；建议修订 → 读取 `review/storybuilding.md`，修订对应产物**一次**，**不再二次审查**，直接进入返回步骤。

返回时包含：是否执行修订、是否有质量风险。
格式：`执行修订：否\n质量风险：无`

### 步骤 5 — 回复

用纯文本简要汇报：
- 产出了哪些维度的骨架
- 骨架覆盖范围（故事核心、主线事件表、核心人物）
- 审查状态（执行修订：是/否；质量风险）
- 下一步建议（基于配比软原则与叙事需要提出方向建议，交用户决定）

## 注意事项
- 全部手写产物执行 storybuilding-specs 文风规范（平实叙述）：短句直说、破折号从简、解释过载先简化设定，不写机制说明书式段落
- 只写入系统提示词中定义的文件路径，不修改 demand.md 或其他文件。
- 维度之间保持一致性：引用其他维度的内容时，确保被引用的内容确实存在。
- 线名、事件名全文件唯一且创建后不改（全景/泳道图按名称归属）；不使用 S/E/G 编号。
- **核心人物克制**：≤ 2 人（不含主角），配角禁止建角色线。角色线是稀缺资源，只给真正长期出场且有独立弧光的核心人物。
