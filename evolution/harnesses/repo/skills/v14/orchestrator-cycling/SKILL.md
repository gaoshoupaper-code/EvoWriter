# orchestrator-cycling

主控编排流程。每轮先看 [配比导航] 指令（系统每轮注入，机械判定），再决定委托。

## 阶段 0 — 读取需求与现状

读取 `demand.md`（核心层目标配比 / 承诺点）与 `storyline.md`（如存在）。

- 工作区无 storyline.md → 进入**初构阶段**
- 已存在 → 进入**增量循环**

## 阶段 1 — 初构（依赖序：worldview → character → storyline）

1. 委托 **worldview**：初构基础世界观框架（时代背景 + 核心冲突根源起步）
2. 委托 **character**：初构主角 + 核心人物骨架（核心人物 ≤ 2）
3. 委托 **storyline**：初构故事核心 + 主线骨架（仅 1 条主线，含 12 事件组 + timeline）
4. 进入增量循环

每步委托中附带 demand 相关摘要（题材、核心创意、设定层倾向），并等待返回后再进行下一步。

## 阶段 2 — 增量循环（由 [配比导航] 驱动）

**模式判定**（以工作区实况为准，不凭感觉）：

**统计当前规模并计算比值 R = C / S**：
- 人物数 C = `character/` 下已有角色档案数
- 故事线数 S = storyline.md 一览表中的故事线行数

| 比值 R | 模式 | 本轮动作 |
|--------|------|---------|
| R ≥ 3（人物充足） | **模式A** | 委托 storyline 新增一条故事线 |
| R < 3（人物不足） | **模式B** | 委托 character 新增一个人物并融入现有故事，**不新增故事线** |

判定后只走对应模式，两种模式互斥。

**防死循环提醒**：若本轮为模式B（新增人物），计算加完后 R 值是否仍 < 3——若是，则连续模式B 会累积人物但永远达不到模式A 阈值。此时应考虑下一轮直接走模式A（新增故事线），避免无限增加人物。

**每轮循环**：
1. 查看 [配比导航]：未达标 → 按上表分流委托对应领域代理
2. 委托返回后，处理跨领域转交（character 代理提出的故事线变更 → 转交 storyline；storyline 代理提出的人物/世界观需求 → 转交对应代理）
3. 达标 / 预算耗尽 → 进入阶段 3

**深入思考该怎么加**（委托前想清楚，不机械套模板）：
- **缺什么**：缺叙事维度（故事线）还是缺角色厚度（人物）？
- **观察已有结构**：事件编排的缝隙、人物关系网的挂点、各线走向与交汇点
- **具体委托**：承接哪条线 / 交汇哪条线、新人物挂哪条关系、关联点在哪——写进委托的「本轮焦点」

## 阶段 3 — 收尾：review 审查 + 按领域分派修订

**触发**：[配比导航] 显示已达标或预算耗尽（无导航指令时自主判断收束：进度长期停滞、主线已推进至终局阶段）。

1. 调用 **review-storybuilding** 审查（**全流程只调用 1 次**）。委托中附上配比达成情况。
2. review 返回后按领域分派修订（DEC-009）：
   - 世界观问题 → 委托 worldview 修订
   - 人物问题 → 委托 character 修订
   - 故事线问题 → 委托 storyline 修订
   - **每个领域代理一次修订机会**，修订后不再二次审查
3. 汇总返回（纯文本）：各维度规模（线数按类型 / 人物数）、配比达成情况、是否执行修订、质量风险

## 注意事项

- 你不直接写入任何创作文件；demand.md 只读
- 委托等待返回后再进行下一步，不并发委托多个领域代理
- 领域代理返回的跨领域需求必须转交，不得丢失
- 每次委托含：领域任务、本轮焦点、用户扩展方向（如有）、前几轮 review 问题（如有）
