# storybuilding-expand-storyline

增量新增故事线流程（原增量技能 storybuilding-expand 的新增故事线半边）。**内容规范唯一真相源是技能 storybuilding-specs**（质量总则/世界观/人物档案/故事线/事件/文风/物品卡全部在其中，系统提示词只管流程）——动笔前读取（本会话已读过则不必重读；写入被护栏弹回时对照错误信息修订），跳读等于无规范写作。本技能只新增故事线；新增人物并融入由技能 storybuilding-expand-character 处理。**公共增量规则（人物引入约束/内容关联约束/世界观同步/写入克制度）声明在系统提示词**，对本技能同样适用。

## 工作流程

### 步骤 0 — 委托含糊判定（增量委托适用）

本技能既可能由用户对话委托发起，也可能由 [配比导航] 驱动自主运行。用户对话发起的委托：三要素（加什么类型——主线续延/支线/角色线/暗线、什么规模、与现有结构什么关系）任一缺失或含糊 → 按系统提示词「方向提案协议」出 2-3 套方向方案（每套五件套，方案间真实不同）经 `confirm_with_user` 交用户拍板，一次有效回复即动笔，不再二次追问；委托明确 → 直接动笔；[配比导航] 驱动的自主运行不问。不要为明确委托制造提问——高频动作的每次多余交互都是摩擦。

### 步骤 1 — 前置检查与自检（无导航时兜底）

- storyline.md 不存在 → 拒绝执行，返回：`错误：storyline.md 不存在，请先使用初构技能 storybuilding-initial 构建故事骨架。`
- **模式指针核对**：[配比导航] 指令有明确指向 → 以导航为准（系统按工作区实况机械核对）；无导航指令（留白档软终止）→ 自行计算：全量读取 storyline.md 数线区块数 S，数 `character/` 档案文件数 C，计算 R = C / S。
  - R < 3（人物不足）→ 拒绝执行，返回：`错误：当前人物/故事线比值 R = C/S < 3，人物不足，本轮应使用技能 storybuilding-expand-character 新增人物。`
  - R ≥ 3 → 继续执行本技能。

### 步骤 2 — 读取已有内容

**全量读取 storyline.md 获取全局视图**（单文件即全局）：故事核心（定位与结局约束）、各线区块（类型、状态、事件编排）。按需读取：demand.md（目标配比）、worldview.md、`character/*.md`（涉及既有人物时）。

### 步骤 3 — 深入思考该怎么加合适

新增故事线不是套模板填空，先想清楚再动笔：

1. **缺什么**：本轮委托焦点指向哪个叙事维度（主线续延 / 支线 / 角色线 / 暗线）？与导航指针、demand 目标配比是否一致？
2. **观察已有结构**：已有线的事件表疏松还是密集、有没有可承接或可插入的时序缝隙；各线的起点、交汇点、走向；已有角色间关系网的复杂度。
3. **怎么加、加什么、加在哪**：承接某条已有线往下写（新线起点接旧线末尾），还是插入一条与已有线交汇的新线？挂到哪条线上、与哪个角色建立因果、关联点（交汇事件 / 关系建立节点）具体在哪？

### 步骤 4 — 产出完整故事线

**4.1 确定新增故事线类型**（类型决定事件数量模板与拓扑角色，类型未定不得动笔）

| 类型 | 适用场景 |
|------|---------|
| 主线（续延） | 推进主干叙事——新建一段主线区块接在主干链后（发展+终局事件） |
| 支线 | 扩展叙事维度，补充主线的世界切面 |
| 角色线 | 为已有核心人物和 Boss 创建独立弧光 |
| 暗线 | 埋设深层信息，制造悬念 |

- **类型选择优先级**：参考 demand 目标配比，优先补「当前数 < 目标」的类型；配比是上限，已满的类型不再新增
- 角色线：必须有对应的核心人物档案（角色类型为「核心人物」或「Boss」），每个核心人物最多 1 条角色线
- 主线可续延：支持新增一段主线（新建主线区块，接主干链后）

**4.2 产出内容**
1. 在 storyline.md 文件末尾新增一个线区块（`## {线名} · {类型} · {状态}` + 线头两行 + 完整事件表）——非交汇事件数按 storybuilding-specs 数量模板执行（系统写前校验，不足/超出模板值都会被弹回）
2. 新事件的时序号嵌入全局时间流：参考已有全部事件的 T 号，插在正确位置用小数号（如 `T7.5`）

**不要新建任何文件、不要维护时间线**——timeline.md 与泳道图由系统自动派生。

**关联约束**（系统提示词公共增量规则适用）：新故事线必须共享 ≥ 1 个已有角色，或与 ≥ 1 条已有故事线有交汇事件；若附带引入新角色，须满足人物引入约束三条；故事线可续写——新线起点与上一线末尾在时间与因果上连续衔接，不重复上一线已写过的内容。

**4.3 事件写入规则**
- 每个事件一行，八列齐全（时序/事件/类型/阶段/地点/角色/交汇/描述），一次写完整区块
- 非交汇事件数必须等于模板值（系统写前校验）；节拍序列为创作指引，按叙事需要编排
- 交汇事件不计入模板计数，独立插入：事件行只写一次（放在剧情因果链的主要承载线区块），「交汇」列列出其他参与线名；必须同时推动 ≥ 2 条故事线的方向改变

**4.4 暗线浮出转支线**

暗线完成 5 个非交汇事件后浮出转为支线：已有事件视为已完成的铺垫；转支线后沿用支线模板追加发展 `危机→冲突→危机→冲突`(4) + 终局 `冲突→胜利`(2)；区块标题行的类型段改为「支线」，事件继承、事件名不变（改名=引用断）。

### 步骤 5 — review 审查（每轮收尾必审一次）

**收尾时机**：每轮运行的导航指令显示单元完成/批次完成/配比达标/预算耗尽时收尾（交互模式默认一轮完成一个增量单元即收；用户指示连写 N 条时由 set_increment_batch 设置批次，N 条线全部落地或配比达标才收）。

收尾时调用 review 子代理审查（**本轮产物有任何修改即须审查**——未审直接返回会被系统闸门拦回）。review 调用上限以当轮批次数为准（默认一轮 1 次；连写批次时已放宽至 4N，超出会被拦截）。连写批次内**每个增量单元完成后各调用一次 review**，不要攒到批次末尾一次性审。

**调用时在任务描述中附加**：
"本次为增量新增故事线，请侧重审查新线与已有线的交汇咬合、全局时序一致性与克制度（不臃肿）。已有内容不应被删除或大幅重写。"

**单次审查策略**：低于标准 → 读取 `review/storybuilding.md`，修订对应产物**一次**，**不再二次审查**，直接进入返回步骤。
返回时包含：是否执行修订、是否有质量风险。
格式：`执行修订：否\n质量风险：无`

### 步骤 6 — 回复

用纯文本简要汇报：
- 新增了哪条故事线（类型、名称）、新增事件数、交汇事件情况
- 当前全局状态（故事线总数、人物总数、当前 R 值）
- 审查状态
- 下一步建议（按导航指针或 R 值：继续新增故事线 / 转新增人物 / 收尾）

## 注意事项

- 全部手写产物执行 storybuilding-specs 文风规范（平实叙述）：短句直说、破折号从简、解释过载先简化设定，不写机制说明书式段落；修订旧条目时同步按此口径改写
- 只写入系统提示词中定义的文件路径，不修改其他文件
- 增量扩展时先读取再修改，不要从零重写已有文件
- 维度之间保持一致性：引用其他维度的内容时，确保被引用的内容确实存在
- 操作前先全量读 storyline.md 获取全局视图——这是最重要的前置步骤
- 模式自检以读取到的实际 C、S 为准，不要凭感觉
- 线名、事件名全文件唯一且创建后不改；不使用 S/E/G 编号
