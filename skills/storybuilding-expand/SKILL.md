# storybuilding-expand

增量故事内容填充流程。每次扩展按**人物/故事线比值 R = 人物数 / 故事线数**分流为两种互斥模式：

- **模式A — 新增故事线**：R ≥ 3（人物充足）时，新增一条完整故事线（自带完整事件表）
- **模式B — 新增人物并融入**：R < 3（人物不足）时，新增一个人物并融入现有故事，**不新增故事线**

每次调用只执行其中一种模式。

## 工作流程

### 步骤 1 — 前置检查

**检查 storyline.md 是否存在：**
- 不存在 → 拒绝执行，返回：`错误：storyline.md 不存在，请先使用初构 Skill 构建故事骨架。`
- 存在 → 继续执行

### 步骤 2 — 模式判定

**全量读取 storyline.md 获取全局视图**（单文件即全局）：
- 故事核心：了解故事定位和结局约束
- 各故事线区块：了解所有现有故事线的类型、状态与事件编排

**按需读取其他文件**：
- 涉及人物 → 读取 `character/*.md`
- 涉及世界观 → 读取 `worldview.md`

**统计当前规模并计算比值 R = C / S**：
- 人物数 C = `character/` 下已有角色档案数
- 故事线数 S = storyline.md 中的线区块数

| 比值 R | 模式 | 本轮动作 |
|--------|------|---------|
| R ≥ 3（人物充足） | **模式A** | 新增一条故事线 |
| R < 3（人物不足） | **模式B** | 新增一个人物并融入现有故事，**不新增故事线** |

判定后只走对应模式，两种模式互斥；以读取到的实际 C、S 为准，不要凭感觉。

**防死循环提醒**：若本轮为模式B（新增人物），计算加完后 R 值是否仍 < 3——若是，则连续模式B 会累积人物但永远达不到模式A 阈值。此时应考虑本轮直接走模式A（新增故事线），避免无限增加人物。

**配比导航（以系统注入的 [配比导航] 指令为准）**：同时读取 demand.md 核心层「目标配比」（主线/支线/角色线/暗线各几条）。
- 系统每轮注入的 [配比导航] 已按工作区实况核对目标 vs 实际；模式A 下决定**本次新增哪种线**时，优先补"当前数 < 目标配比"的类型；目标配比是上限，已满的类型不再新增。
- **主线可续延**：模式A 也支持新增一段主线（新建主线区块，接主干链后），用于推进主干叙事。
- **收束判断**：导航显示已达标/预算耗尽时停止增量转入收尾（见步骤 4）；无导航指令（软终止模式）时按"进度长期停滞、主线已推进至终局"等信号自行判断。

### 步骤 3 — 深入思考该怎么加合适

模式判定只决定了"加故事线还是加人物"，但具体加什么、怎么加、加在哪还得先想清楚，避免机械套模板。按以下顺序思考：

1. **缺什么**
   本次委托焦点指向缺叙事维度（缺故事线）还是缺角色厚度（缺人物）？与步骤 2 的 R 值判定是否一致。

2. **观察已有内容的结构**
   先读懂现状再决定怎么加：
   - 事件紧密度：已有故事线的事件表疏松还是密集？有没有可承接或可插入的时序缝隙？
   - 人物关系复杂度：已有角色间的关系网是单线还是交织？新内容该挂到哪条关系上？
   - 故事线走向：各线的起点、交汇点、走向，判断新内容与哪条线咬合最有张力。

3. **怎么加、加什么、加在哪**
   基于上一步的观察，确定具体加法：
   - 是承接某条已有故事线往下写（新线起点接旧线末尾），还是插入一条与已有线交汇的新线？
   - 新人物是前瞻登场（最新事件之后追加）还是回溯嵌入（微调已有事件）？
   - 落到哪条线、与哪个角色建立因果、关联点（交汇事件 / 关系建立节点）具体在哪？

4. **按照规则去加**
   想清楚后，进入下方对应模式的详细规则执行（模式A / 模式B + 公共规则）。

## 模式A — 新增故事线

（当 R ≥ 3 时执行）

### A.1 确定新增故事线类型

**约束：先判别本次新增的是什么线（主线续延 / 支线 / 角色线 / 暗线），再编排内容——类型决定事件数量模板与拓扑角色（主线串行、其余与主线并行），类型未定不得动笔。**

根据委托中的"本轮焦点"和"用户扩展方向"，确定本次新增的故事线类型：

| 类型 | 适用场景 |
|------|---------|
| 主线（续延） | 推进主干叙事——新建一段主线区块接在主干链后（发展+终局事件） |
| 支线 | 扩展叙事维度，补充主线的世界切面 |
| 角色线 | 为已有核心人物和BOSS创建独立弧光 |
| 暗线 | 埋设深层信息，制造悬念 |

**类型选择优先级**：参考 demand 目标配比，优先补"当前数 < 目标"的类型；配比是上限，已满的类型不再新增。

**类型选择约束**：
- 角色线：必须有对应的核心人物档案（角色类型为"核心人物"或"Boss"），每个核心人物最多 1 条角色线
- 暗线：适合需要隐藏信息逐步揭示的叙事需求
- 支线：最通用的扩展方式

### A.2 产出完整故事线

按系统提示词中的内容规范和事件数量模板，新增一条完整故事线。

**产出内容**：
1. 在 storyline.md 文件末尾新增一个线区块（`## {线名} · {类型} · {状态}` + 线头两行 + 完整事件表）——非交汇事件数按系统提示词 §5.1 数量模板执行（系统写前校验，不足/超出模板值都会被弹回）
2. 新事件的时序号嵌入全局时间流：参考已有全部事件的 T 号，插在正确位置用小数号（如 `T7.5`）

**不要新建任何文件、不要维护时间线**——timeline.md 与泳道图由系统自动派生。

**关联约束**：
- 新故事线必须与 ≥ 1 条已有故事线有交汇事件
- 交汇事件独立于事件数量模板，作为额外插入的特殊事件；事件行只写一次（放在剧情因果链的主要承载线区块），「交汇」列出其他参与线名
- 模式A 下若需附带引入新角色，仍须满足下方"人物引入约束"
- 故事线可续写：新增的故事线可承接上一条故事线的末尾往下写，新线起点与上一线末尾在时间与因果上连续衔接，不重复上一线已写过的内容

#### A.3 事件写入规则

- 每个事件一行，八列齐全（时序/事件/类型/阶段/地点/角色/交汇/描述），一次写完整区块
- 非交汇事件数必须等于模板值（系统写前校验）；节拍序列为创作指引，按叙事需要编排
- 交汇事件不计入模板计数，独立插入

#### A.4 暗线浮出转支线

暗线完成 5 个非交汇事件后浮出转为支线：

- 暗线的已有事件视为已完成的铺垫
- 转支线后沿用支线模板：追加发展 `危机→冲突→危机→冲突`(4) + 终局 `冲突→胜利`(2)
- 区块标题行的类型段改为「支线」，事件继承、事件名不变（改名=引用断）

## 模式B — 新增人物并融入

（当 R < 3 时执行。本轮**不新增故事线**，只新增一个人物并融入现有故事）

### B.1 设计人物档案

按系统提示词的角色档案规范，新建 `character/{角色名}.md`，包含完整段落（基本信息、角色类型、叙事结构功能、外貌特征（四层规范见系统提示词 §3.1）、性格特质、关系网络、人物状态线）。

**更新已有角色档案时**：若旧档案含已废弃段落（角色弧光、能力与局限），移除这两个段落、归一为新 6 段格式；其余段落不动。

**角色类型选择**：依据该人物在已有故事中要承担的功能，选 核心人物 / Boss / 配角（主角一般初构已定，不在此新增）。

### B.2 选定融入目标

融入不是把人物"贴"进故事，而是让他与已有结构产生因果。必须明确：

- **服务于哪条/哪几条已有故事线**（≥ 1 条）：新人物在哪条线上发挥作用
- **与哪个已有角色建立核心关系**（≥ 1 个）：关系类型（血缘/利益/恩怨/师徒/情感……）+ 动态变化方向

### B.3 融入方式（二选一或组合）

| 方式 | 做法 | 适用 |
|------|------|------|
| **前瞻登场** | 不改动任何已有事件；在目标故事线区块事件表**末尾追加**新事件行（时序号接全局最新之后），让新人物在此首次登场并承担叙事功能，其过往借"揭露/悬念"自然带出 | 常规引入新人物 |
| **回溯嵌入** | 选取 4-5 个已有事件行，把新人物加入其"角色"列，并**微调事件描述**以体现他的作用（如：他才是暗中激化冲突者、他提供了关键情报） | 伏笔回填——让读者感觉发现"这人一直在" |

**优先使用前瞻登场**；回溯嵌入须谨慎，且只微调、不推翻原事件核心。

### B.4 融入功能性要求（让融入"有用"而非贴牌）

- **承担明确功能**：新人物在所融入事件中必须是某种叙事功能的承担者——冲突制造者 / 关键信息提供者 / 力量变量（改变强弱对比）/ 情感锚点，不能只在"角色"列个名字
- **制造新张力**：新人物的加入要打破现有平衡，制造新的冲突、危机或悬念（呼应系统提示词的"戏剧张力/危机感"原则）
- **关系可演变**：与已有角色的关系要有"动态变化方向"（会发展、逆转或加深），不是静态标签

### B.5 融入落点（写入哪些文件）

| 文件 | 写入内容 |
|------|---------|
| `character/{新人物}.md` | 新建完整角色档案；"关系网络"含与 ≥ 1 已有角色的关系 |
| `storyline.md` 目标故事线区块 | 前瞻：事件表末尾追加新事件行，新人物在"角色"列；回溯：修订目标事件行的"角色"和"描述" |
| 相关已有角色 `character/{已有角色}.md` | 在"关系网络"补与新人物的关系（双向一致） |

模式B **不新增线区块**（本轮不新增故事线），也**不维护时间线**（系统自动派生）。

## 公共规则（两种模式共用）

### 人物引入约束

模式B 必须全部满足；模式A 若附带新角色也须满足：

1. 与 ≥ 1 个已有角色有关系（血缘/利益/恩怨/师徒……）
2. 服务于 ≥ 1 条已有故事线（不能自带一条全新独立线进来）
3. 引入事件与已有事件有时空或因果交集

### 内容关联约束

所有新增内容不得完全独立：

| 新增类型 | 最低关联要求 |
|----------|-------------|
| 新故事线（模式A） | 共享 ≥ 1 个已有角色，或与 ≥ 1 条已有故事线有交汇事件 |
| 新人物（模式B） | 满足上方三条引入约束，并按 B.3 融入目标故事线 |
| 交汇事件 | 必须同时推动 ≥ 2 条故事线的方向改变 |

### 世界观同步

- 扩展中出现**新势力**（组织/门派/种族/国家）→ 同步写入 worldview.md
- 扩展中出现**新地点**（城市/区域/地标）→ 同步写入 worldview.md
- 写入最低信息量：名称、与已有势力的关系、在当前事件中的立场

### 写入顺序与克制度

写入顺序（按需）：
1. `worldview.md`（先读取，按需深化）
2. `character/*.md`（模式B 新建新人物档案 + 更新已有角色关系网络）
3. `storyline.md`（模式A 在文件末尾新增线区块；模式B 在既有区块内追加/修订事件行）

**克制度原则**：
- 只添加本次目标明确需要的内容，不做预防性扩展
- 已有内容不应被删除或大幅重写（回溯嵌入仅限微调目标事件行）；编辑 storyline.md 时不要动无关线区块
- 不创建 storyline/ 目录，不创建/编辑 timeline.md——全景时间轴由系统自动派生

---

### 步骤 4 — review 审查（每轮收尾必审一次）

**收尾时机**：每轮运行的导航指令显示单元完成/批次完成/配比达标/预算耗尽时收尾（交互模式默认一轮完成一个增量单元即收；用户指示连写 N 条时由 set_increment_batch 设置批次，N 条线全部落地或配比达标才收）。

收尾时调用 review 子代理审查（**本轮产物有任何修改即须审查**——未审直接返回会被系统闸门拦回）。review 调用上限以当轮批次数为准（默认一轮 1 次；连写批次时已放宽至 4N，超出会被拦截）。连写批次内**每个增量单元完成后各调用一次 review**（人物单元也审——关系网络双向一致、回溯嵌入不推翻原事件是审查重点），不要攒到批次末尾一次性审。

**调用时在任务描述中附加**：
"本次为增量填充，请侧重审查新增内容与已有内容的一致性和克制度（不臃肿）。已有内容不应被删除或大幅重写。"

**单次审查策略**：
- 低于标准 → 读取 `review/storybuilding.md`，修订对应产物**一次**，**不再二次审查**，直接进入返回步骤。

返回时包含：是否执行修订、是否有质量风险。
格式：`执行修订：否\n质量风险：无`

### 步骤 5 — 回复

用纯文本简要汇报：
- 本轮执行的模式（A 新增故事线 / B 新增人物并融入）
- 模式A：新增了哪条故事线（类型、名称）、新增事件数、交汇事件情况
- 模式B：新增了哪个人物（角色类型）、融入到哪条故事线、采用前瞻/回溯、对该线做了什么
- 当前全局状态（故事线总数、人物总数、当前 R 值）
- 审查状态
- 下一步建议（若 R 仍 < 3，建议下轮继续模式B；否则可走模式A）

## 注意事项

- 全部手写产物执行系统提示词 §6.5 文风规范（平实叙述）：短句直说、破折号从简、解释过载先简化设定，不写机制说明书式段落；修订旧条目时同步按此口径改写
- 只写入系统提示词中定义的文件路径，不修改其他文件。
- 增量扩展时先读取再修改，不要从零重写已有文件。
- 维度之间保持一致性：引用其他维度的内容时，确保被引用的内容确实存在。
- 操作前先全量读 storyline.md 获取全局视图——这是最重要的前置步骤。
- 模式判定以读取到的实际 C、S 为准，不要凭感觉。
- 线名、事件名全文件唯一且创建后不改；不使用 S/E/G 编号。
