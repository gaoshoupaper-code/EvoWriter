# storybuilding-specs · 内容规范手册

四类手写产物（storyline / character / worldview / object）内容规范的唯一真相源：流程技能（初构/增量）在动笔前引导你到这里，review 审查器的判据同样以本规范为准。规范中的结构数值（事件数量模板、物品卡格式与轨迹枚举）由系统护栏强制校验，违规写入会被弹回并附带差距说明——以护栏错误信息为最终口径。

## 一、质量总则

细则管格式，总则管产物好不好读。格式全对而违背总则，仍是坏产物。

大纲的第一读者，是之后拿着它写正文的人。他不分享你脑中的图景，只读你写下的字。

**清晰是替读者做功。** 他读任何一句话的成本——卡住、回翻、存疑、重读——都是你没替他付掉的功。术语当场讲清，主线的事在主线里讲完，因果按发生顺序直说；寓意和抒情不挤进事件行。什么都说，等于什么都没说清——取舍是作者的活，删也是做功。写完自问：他读完能复述吗？

**现场只有一个。** 故事只在事件表里发生：谁做了什么、伤在何处、东西归谁，一律以事件表为准；人物状态线、物品卡、世界观都是它投下的影子。故事往前走了，影子要跟着动——影子停在原地，就是矛盾。

**没有草稿纸，设定是活的。** 写进产物的每个字，读者都会当成正式设定；写给自己的备忘与待办，不进文件。设定不刻在石头上——故事长了、想法变了，回头修订旧设定是常态；改，就把相关产物一起改齐。

## 二、世界观（worldview.md）

单文件，只写与故事有关的：

- 时代背景、地理空间、社会结构
- 核心规则（力量体系/社会法则）
- 历史脉络（仅影响故事的）
- 核心张力（世界矛盾与对立）

### 2.1 世界观表达原则

世界观是全书的地基，把逻辑写透比写得短重要，需要篇幅就花篇幅，不压缩成读者猜谜。

- **逻辑是第一生命力**：每条核心规则经得起一句「为什么」的追问。修辞可以加味，比喻不能代替解释；设定之间不互相打架
- **清晰是第一表达标准**：一遍读懂。术语可雅、不可无解——功法、物品、机制、境界等名词，首次出现时读者必须能从上下文读懂它指什么

## 三、人物（character/{角色名}.md）

每个角色一个文件，固定段落（顺序一致）：

- **基本信息**：姓名、年龄、性别、身份
- **角色类型**：主角 / 核心人物 / Boss / 配角
- **叙事结构功能**：该角色在叙事中的结构作用
- **外貌特征**：四层结构（底子 / 穿着 / 记忆点 / 神态），规范见 3.1
- **性格特质**：核心标签 + 行为标识（用行为定义性格）
- **关系网络**：与各角色的关系类型 + 动态变化方向
- **人物状态线**：按事件节点（T 号锚点）记录已发生的状态变化。功法/武技：何时何地、因何事件获得；境界等级：哪个节点什么等级、何时跳变；关键物品：何时得/失

**角色档案软定性**：档案只定义「这个人是谁」。不预写剧情走向。人物状态线只记录 storyline 事件表已发生的变化，不预写未发生的走向；已发生的变化必须记录。

### 3.1 外貌段四层规范

外貌特征段按四层组织，自然成段即可，不必分条列点：

- **底子**：身量、脸、肤色、发等先天条件。主角与 Boss 必须美且具体，实写物象，不用「清秀」「明艳」这类一笔带过的虚词
- **穿着**：常穿衣饰。映射身份、地位、所处环境（宗门制式、坊市粗布、世家气派），是读者判断人物处境的第一线索
- **记忆点**：一个独有特征，全书只此人有。一双眼、一道疤、一件常伴之物皆可，自由命题，不限定类型
- **神态**：动态气质。怎么看人、怎么说话、静下来是什么样

按角色类型分级：

| 角色类型 | 外貌段要求 |
|---------|-----------|
| 主角 / Boss | 四层全有，底子必须美且具体 |
| 核心人物 | 底子、穿着、记忆点三层为底线，可适当压缩 |
| 配角 | 一两笔抓人特征，不铺陈 |

美感表达落物象、不落堆砌：「眉眼清疏、静时眼底也有光」是物象；「倾国倾城、绝色无双」是堆砌，禁止。外貌段不适用 6.1 创作原则中事件描述的「禁止具体化」条款，但 6.2 文风规范的平实句式（短句直说、破折号从简）仍适用。

**角色类型与角色线资格**：

| 类型 | 定义 | 角色线 |
|------|------|--------|
| 主角 | 核心视点人物，叙事驱动者，弧光融入主线 | 不单独建线 |
| 核心人物 | 长期出场、有贯穿多卷独立弧光的关键角色，不分正邪（盟友/对手/导师/宿敌皆可） | 可建线（每人至多 1 条） |
| Boss | 主角必须跨越的强敌，具备独立动机与清晰威胁等级，按核心人物对待 | 可建线 |
| 配角 | 功能性角色，服务特定事件或场景 | **禁止建线**（叙事功能写在事件「角色」列） |

角色名字要普通、容易记住，不要太土气或太有网文味。

## 四、故事线

故事核心定调 → 故事线按方向组织事件表 → 事件标记状态跳变；交汇事件是多线叙事的编织节点。

### 4.1 storyline.md 总体结构与故事核心

严格按此顺序：**故事核心**（文件头）→ **故事线区块**（一线一区块，追加新线时在文件末尾新建区块）。

故事核心固定五字段：**Logline / 核心主题 / 类型基调 / 节奏曲线 / 最终结局**。

### 4.2 概念

故事线只写事件串联的**方向和走向**，本身不含具体情节：写极简方向（如「从被压制到反击」）+ 事件表；不写过程展开、过渡内容。

### 4.3 线类型与拓扑

| 类型 | 叙事功能 | 典型生命周期 |
|------|---------|--------------|
| 主线 | 驱动核心叙事推进，承载主题表达与主角成长 | 贯穿全局 |
| 支线 | 扩展叙事维度，补充主线的世界切面 | 按叙事逻辑自然收束 |
| 角色线 | 塑造核心人物（非主角）的独立弧光，该核心人物是这条线的主角、占最多篇幅 | 可跨线延续 |
| 暗线 | 埋设深层信息，制造悬念和认知差 | 埋设→浮出→转支线（流程见增量技能） |

- **主线串行**：主线是叙事主干，事件按时间线性串联；多段主线（多卷）首尾相接，构成单条主干链
- **其余线并行**：支线/角色线/暗线通过**交汇事件**与主线（及彼此）咬合，起止不必与主线严格同步
- 状态标签（区块头第三段）：活跃 / 已收束 / 可浮出 / 浮空

### 4.4 交汇事件（多线碰撞的结构节点）

同时属于**两条或以上故事线**的事件，全局只写**一次**：

- 事件行物理写在剧情因果链的**主要承载线**区块，「交汇」列列出其他参与线名（顿号分隔）；其他线不重复定义
- 作为**额外插入的特殊事件**，不计入各线事件数量模板（5.1）
- 写它如何同时推动多条线的方向改变，不写各条线的独立发展

交汇是保持多线叙事紧凑的关键：一条事件同时服务多条线，避免各线各自铺排导致事件膨胀。

### 4.5 区块格式（一线一区块）

```
## {线名} · {类型} · {状态}

- 主要地点：1-3 个主要发生地，与世界观场地呼应
- 全局走向：整条线的总体方向，简要串一下事件，不花过多篇幅

| 时序 | 事件 | 类型 | 阶段 | 地点 | 角色 | 交汇 | 描述 |
|------|------|------|------|------|------|------|------|
| T1 | 灭门之夜 | 冲突 | 发展 | 青云宗 | 林寒 | | 一夜之间家破人亡，是仇杀还是阴谋？ |
| T7.5 | 祭祖大典的闯入 | 冲突 | 发展 | 青云宗 | 林寒、林玄霜 | 感情线、暗流线 | 当众闯坛撕开旁支伪面，两条线的走向同时被改写。 |
```

- **线名、事件名全文件唯一，创建后不改**。它们是全景时间轴、泳道图与配比计数的引用锚点；不使用 S/E/G 类编号，引用时直接写名称（结构合法性由系统校验）

### 4.6 关键规则

- **最终结局草稿制**：storyline.md 的「最终结局」初构定为草稿基线，后续轮次可随叙事需要修订；修订时终局事件与 Logline 同步对齐（review 把关；护栏对结局类违规豁免拦截）
- **主线承载主角成长**：主角没有独立角色线，弧光融入主线事件
- **角色线以核心人物为主角**：该核心人物在全线事件「角色」列排第一位、占最多篇幅
- **非主线自然收束**：支线、角色线完成叙事使命后自然收束

## 五、事件

事件是故事线的最小叙事单元，以**表格行**写入所属线区块；没有事件组层级，幕结构用「阶段」列表达。

### 5.1 数量模板（非交汇计数，系统写前校验）

| 线类型 | 非交汇事件数 | 建议节拍序列 |
|--------|-------------|--------------|
| 主线 | 12 | 发展 8：冲突→危机→反转→悬念→冲突→危机→反转→揭露；终局 4：危机→冲突→反转→胜利 |
| 支线 | 6 | 发展 4：危机→冲突→危机→冲突；终局 2：冲突→胜利 |
| 角色线 | 5 | 弧光：冲突→危机→冲突→危机→反转 |
| 暗线 | 5 | 悬念→冲突→危机→反转→揭露 |

- 数量是硬约束：新增线区块按模板**整线写入、一次写完整区块**；非交汇事件数不足或超出模板值都会被系统弹回
- 节拍序列是创作指引（软约束，由 review 把关）；交汇事件额外插入、不计入计数

### 5.2 事件表列语义（列序固定）

| 列 | 写什么 |
|----|--------|
| 时序 | 全局时序号 `T{n}`，跨全部线统一编号；插入既有时间流用小数（如 `T7.5`） |
| 事件 | 事件名，全文件唯一，创建后不改 |
| 类型 | 叙事功能类型（5.3），只写类型词 |
| 阶段 | 幕结构标签（如 发展/终局），自由短语 |
| 地点 | 事件发生地，与线级「主要地点」呼应 |
| 角色 | 参与角色，顿号分隔；角色线的主角排第一位 |
| 交汇 | 仅交汇事件填写其他参与线名；普通事件留空 |
| 描述 | 发生了什么、状态怎么变了，按因果顺序用平实短句直说（文风规范见 6.2）；历法时间（三日后/入冬/次年）并入描述表达；不做旁白解释，不堆动作语言细节（留给写作阶段） |

### 5.3 事件类型（叙事功能分类，按底层机制判定而非字面情节）

| 类型 | 核心本质 | 节奏作用 |
|------|---------|---------|
| 冲突 | 意志的直接对抗：对立目标/利益/价值观正面碰撞，形成「要 A 就必须克服 B」的障碍结构 | 故事发动机，持续输出张力 |
| 危机 | 选择空间坍缩：代价显性化，被逼到「两害相权、无可拖延」的临界点 | 把冲突推上峰值，拉高风险线 |
| 反转 | 前提被推翻：用已有事实重新解读，「一直是 A，却被理解成了 B」 | 制造惊喜，重置判断框架 |
| 揭露 | 隐藏信息显形：被遮蔽的真相浮出水面，直接改变对局势的理解 | 关闭认知缺口，推动理解跃迁 |
| 悬念 | 维持未解张力：已抛出的问题刻意悬置、延迟给答案 | 拉长期待曲线，保鲜好奇心 |
| 胜利 | 张力释放与结算：一条线（或阶段）的能量在此兑现 | 紧张度下行，给满足感与喘息 |
| 交汇 | 独立因果链耦合：分离的故事线相互影响，产生单线不会有的结果 | 多线编织节点，收紧节奏 |

**易混边界**：

- 设谜→延谜→揭谜（同一悬念线的三个节拍）：悬念撕开缺口 → 悬念维持缺口 → 揭露关闭缺口
- 冲突 ≠ 危机：冲突是对抗本身，可长期拉锯；危机是选项坍缩、必须抉择。冲突造阻力，危机造临界
- 揭露 ≠ 反转：揭露是「不知道→知道了」（补信息）；反转是「以为 A→其实是 B」（换框架）

## 六、创作原则与文风规范

### 6.1 创作原则

- 使用中文撰写；情节紧凑、事件密度高，每个事件必须推动至少一条线前进，拒绝注水填充
- 戏剧张力：真实的挫折与有代价的胜利；主角的成功来之不易，对手具备主动威胁能力，不写碾压叙事
- **平实叙述**：全部手写产物统一执行 6.2 文风规范（短句直说、破折号从简、解释过载先简化设定）
- 突出事件性质：描述突出冲突/危机/反转等的本质与状态跳变，事件之间清晰区分；事件描述禁止追求画面感、场景细节、对话动作（这些留给写作阶段）。此禁令仅限事件描述；人物档案外貌段按 3.1 执行，不受此限

### 6.2 文风规范：平实叙述（全部手写产物适用）

storyline、worldview、character、object 四类手写产物统一执行。

**总则**：

- 短句、大白话、按因果顺序直说：谁做了什么、结果如何，读一遍就能复述
- 本规范适用全部四类手写产物（含外貌段）：句式与破折号规则不豁免；外貌段的美感表达边界见 3.1
- 描述的职责是**叙述发生了什么**，不是向读者解释设定如何运作；机制说明书式的段落一律不写
- 破折号从简：一处文本（一个表格格、一个条目、一段）破折号至多一个，且只用于真正的注解；不拿破折号做因果或转折的解释胶水。线头「全局走向」的箭头式串联（→）不受此限

**解释密度分层（硬规则）**：

- **重复展开的解释**：同一意思换个角度再说一遍（先说机制、再打个比方、再补一句「也就是说」）。无条件压掉
- **机制本体的首次定义**：金手指、核心规则怎么运作、代价是什么。允许分层次，但每一层必须自己站得住，层与层之间不许互相解释；某一层要靠另一层来解释，即视为过载
- 总判据：**一句话说不清的设定，先怀疑设定过复杂**。优先简化设定本身（合并机制、砍掉冗余环节），而不是把话说得更绕

**正反例对照**（事件描述实例）：

反例（解释腔，禁止）：
> 十年闺蜜一夜反目：苏晚的洗髓莲台机缘被程鸢窃夺，罪名反扣到她头上，公审台上程鸢一脚踩着她的头宣判——丹田被废、逐出宗门，血仇立下。

正例（平实叙述）：
> 程鸢窃走苏晚的洗髓莲台，反诬她偷窃。公审台上，程鸢踩着苏晚的头宣判。苏晚被废丹田，逐出宗门。

信息一条不丢，三句说完。每写一条描述自查一遍：能不能像正例这样拆成短句直说？拆不动，就是设定过复杂，回去先简化设定。

## 七、物品卡（object/{物品名}.md）

物品轨迹是大纲规划的一部分：每个关键物品一张卡，从出场到易主到损毁逐事件记录，防「已毁又出场」「一把剑两个主人」类穿帮。

### 7.1 建卡门槛（满足任一即建卡）

1. 出现在**主线**事件表里
2. 有归属或状态变化（易主、损坏、升级、消耗……）
3. 承担伏笔

不满足的物品**不建卡**，只在事件描述里提及。全书核心物品控制在**约 15 张以内**。不够格的坚决砍掉，批量制式物品（一百把制式剑）不建卡。

### 7.2 卡片格式（三段式，顺序固定）

```markdown
# {物品名}

## 基本信息

- 名称：{物品名，与文件名完全一致}
- 类型：功法 / 武技 / 武器 / 丹药 / 材料 / 其他（六选一）
- 叙事可见性：明线 / 暗线 / 伏笔（三选一）
```

### 7.3 建卡时机

首发流程：**故事线全部完成后、调用 review 前**，扫一遍事件表按门槛集中建卡——事件表已定稿，锚点稳定，review 也能审到物品。

增量修订：涉及剧情或物品变动的修订，**必须同步维护**受影响的卡片轨迹（修订涉及剧情或物品变动时必读并同步维护）。删除或改名 storyline 事件前，先更新引用它的卡片轨迹。否则 storyline 写入会被系统反查拦截。

### 7.4 暗线纪律

叙事可见性为「暗线」或「伏笔」的物品：读者尚不知道的信息（真实来历、隐藏归属、真实作用）**不得出现在明线事件的描述里**。大纲文本按读者视角写作，全知信息只留在卡片内。
