# storyline-build

故事线维度构建流程（初构 + 增量两种委托）。

## 初构（orchestrator 依赖序第三位，世界观与核心人物已就绪）

两个硬性约束：
1. **只生成主线（1 条）**。支线 / 暗线 / 角色线一律交给增量委托后续添加，初构阶段不生成。
2. **storyline.md "故事核心"段落的"最终结局"描述确定后不可更改**。

动笔前先读取 `worldview.md` 与 `character/*.md`（人物在世界观中活动）。

写入顺序：
1. `storyline.md`（故事核心 + 故事线一览表，仅主线 1 行）
2. `storyline/S01-{主线名}.md`（主线详情 + 完整事件组）
3. `storyline/timeline.md`（汇总主线全部 12 个事件，按时间序成表，归属列仅 S01）

**最小骨架必须包含**：
- storyline.md 中的"故事核心"（Logline、核心主题、类型基调、节奏曲线、最终结局）
- storyline.md 中的故事线一览表（仅 1 条主线）
- storyline/S01-{主线名}.md：主线详情 + 完整两幕事件组（发展 8 + 终局 4 = 12 个事件）
- storyline/timeline.md：全局事件时间线表（主线 12 事件按时间序，归属列 S01 全打✓）

其他维度可以留占位符（标注"待后续轮次补充"）。ID 编号从 01/001 开始。

## 增量 — 模式A：新增一条完整故事线（当 R ≥ 3 时执行）

### A.1 确定新增故事线类型

**约束：先判别本次新增的是什么线（主线续延 / 支线 / 角色线 / 暗线），再编排内容——类型决定事件组模板与拓扑角色（主线串行、其余与主线并行），类型未定不得动笔。**

| 类型 | 适用场景 |
|------|---------|
| 主线（续延） | 推进主干叙事——新建一段主线接在主干链后（发展+终局事件组） |
| 支线 | 扩展叙事维度，补充主线的世界切面 |
| 角色线 | 为已有核心人物和BOSS创建独立弧光 |
| 暗线 | 埋设深层信息，制造悬念 |

**类型选择优先级**：orchestrator 委托中会给出目标配比缺口；优先补"当前数 < 目标"的类型；配比是上限，已满的类型不再新增。

**类型选择约束**：
- 角色线：必须有对应的核心人物档案（角色类型为"核心人物"或"Boss"），每个核心人物最多 1 条角色线
- 暗线：适合需要隐藏信息逐步揭示的叙事需求
- 支线：最通用的扩展方式

### A.2 产出完整故事线

按系统提示词中的内容规范和事件组模板，新增一条完整故事线。

**产出内容**：
1. 新建 `storyline/S{XX}-{名}.md`，写入故事线详情（S{XX}，含全局走向）+ 完整事件组：
   - 主线：发展(8) + 终局(4)
   - 支线：发展(4) + 终局(2)
   - 角色线：弧光(5)
   - 暗线：悬念→冲突→危机→反转→揭露(5)
2. 在 storyline.md 的故事线一览表追加一行
3. 维护 `storyline/timeline.md`：新增归属列 S{XX}；将本线全部事件按全局时间序插入正确位置（更新后续行序号）；交汇事件在对应行 S{XX} 列打✓

**关联约束**：
- 新故事线必须与 ≥ 1 条已有故事线有交汇事件
- 交汇事件独立于事件组模板，作为额外插入的特殊事件；详情只写在本线文件（交汇时主属线=ID 最小者）
- 模式A 下若需附带引入新角色：人物档案不在你的写权限内——在返回摘要中向 orchestrator 说明人物需求（角色功能、关联约束），由其委托 character 代理执行；事件中可先以参与角色名占位引用
- 故事线可续写：新增的故事线可承接上一条故事线的末尾往下写，新线起点与上一线末尾在时间与因果上连续衔接，不重复上一线已写过的内容

### A.3 事件组插入规则

- 按模板固定序列生成，不可跳过、调换或拆分
- 每个事件独立拥有 E{XXX} ID 和完整字段
- 同组事件共享 G{XX} 组 ID
- 交汇事件不属于任何事件组，独立插入

## 公共规则 — 内容关联约束

所有新增内容不得完全独立：

| 新增类型 | 最低关联要求 |
|----------|-------------|
| 新故事线（模式A） | 共享 ≥ 1 个已有角色，或与 ≥ 1 条已有故事线有交汇事件 |
| 交汇事件 | 必须同时推动 ≥ 2 条故事线的方向改变 |

## 注意事项

- 只写 `storyline.md` 与 `storyline/*.md`，不修改 demand.md、worldview.md 或人物文件
- 增量时先读取 storyline.md（核心+一览表）获取全局视图，按需读取相关 `storyline/S{XX}-{名}.md`——这是最重要的前置步骤
- 世界观扩展需求（新势力/新地点）在返回摘要中说明，由 orchestrator 委托 worldview 代理同步
- ID 一旦创建不再变更
- 返回摘要含：新增了哪条线（类型、名称）、新增事件数、交汇事件情况、需要 orchestrator 转交的人物/世界观需求（如有）
